MISSION — CRÉER LA PAGE « LE CŒUR BATTANT DU MONDE »

Je souhaite créer dans AIME une nouvelle expérience majeure : une page mondiale immersive qui permet d’observer, comprendre et ressentir l’activité de la planète en temps réel.

Cette page ne doit surtout pas ressembler à un simple dashboard de statistiques, ni à un site de data visualisation classique.

Le concept est beaucoup plus ambitieux :

Le monde entier devient une Partition Vivante.

Chaque événement, chaque naissance, chaque mariage, chaque transaction, chaque déplacement, chaque dépense publique, chaque variation financière, chaque émission invisible ou chaque mouvement humain devient potentiellement un événement inscrit dans le temps.

La Timeline AIME devient ainsi une forme de chronologie universelle.

Nom de travail de cette expérience :

AIME — LE CŒUR BATTANT DU MONDE

Sous-titre possible :

Observer le monde comme une partition vivante.

⸻

1. VISION GÉNÉRALE

Je veux créer une page immersive basée sur une carte mondiale interactive en arrière-plan.

Cette carte représente la Terre comme un organisme vivant.

Par-dessus cette carte circulent différentes couches d’informations.

Le visiteur peut observer simultanément :

* ce qui se passe maintenant ;
* ce qui vient de se produire ;
* les rythmes du monde ;
* les synchronisations ;
* les flux financiers ;
* les flux humains ;
* les flux environnementaux ;
* les flux sociaux ;
* les événements de vie ;
* les événements institutionnels ;
* les événements invisibles.

L’expérience doit donner la sensation que :

La planète possède son propre rythme cardiaque.

⸻

2. LA MAP MONDIALE COMME FOND PRINCIPAL

Créer une grande carte mondiale immersive occupant pratiquement tout l’écran.

La carte ne doit pas être traitée comme un simple fond statique.

Elle doit devenir le véritable espace de navigation.

Elle doit pouvoir accueillir :

* des points ;
* des pulsations ;
* des flux ;
* des lignes ;
* des trajectoires ;
* des zones de densité ;
* des halos ;
* des particules ;
* des événements temporels.

L’utilisateur doit pouvoir :

* zoomer ;
* dézoomer ;
* déplacer la carte ;
* sélectionner un pays ;
* sélectionner une ville ;
* sélectionner une zone ;
* cliquer sur un événement ;
* isoler un flux de données ;
* remonter ou avancer dans le temps.

La carte doit fonctionner comme un organisme visuel dynamique.

⸻

3. LA TIMELINE UNIVERSELLE

Toute la page doit être directement connectée à la logique de Timeline existante dans AIME.

La Timeline ne représente plus uniquement :

* un mariage ;
* un projet ;
* une vie ;
* un événement.

Elle devient capable de représenter plusieurs échelles simultanément :

Échelle 1 — L’instant

Exemples :

* naissance ;
* mariage ;
* décès ;
* décollage d’avion ;
* transaction ;
* variation boursière ;
* séisme ;
* événement climatique ;
* dépense ;
* déplacement ;
* émission mesurée.

⸻

Échelle 2 — La journée

Ce qui se produit aujourd’hui dans le monde.

Exemples :

* nombre de naissances ;
* nombre de mariages ;
* nombre de vols ;
* dépenses publiques ;
* consommation énergétique ;
* pollution ;
* transactions financières.

⸻

Échelle 3 — L’année

Ce qui permet d’observer :

* évolution démographique ;
* budget d’un État ;
* dette ;
* dépenses ;
* croissance ;
* émissions ;
* évolution de la précarité.

⸻

Échelle 4 — L’histoire

La Timeline doit pouvoir remonter très loin.

Par exemple :

* année de naissance des populations ;
* évolution démographique ;
* événements historiques ;
* évolution des marchés ;
* évolution des États ;
* évolution environnementale.

⸻

4. LE CONCEPT DES SYNCHRONISATIONS

C’est un élément extrêmement important.

Comme tous les événements sont inscrits dans une logique temporelle commune, AIME doit pouvoir détecter et mettre en scène des synchronisations.

Par exemple :

Combien de personnes sont nées exactement le même jour ?

Puis :

Combien sont nées à la même heure ?

Puis éventuellement :

Combien d’événements similaires ont eu lieu simultanément ailleurs dans le monde ?

Créer un module :

SYNCHRONISATIONS

Il doit pouvoir détecter visuellement des phénomènes comme :

* naissances simultanées ;
* mariages simultanés ;
* événements historiques à la même date ;
* pics d’activité simultanés ;
* synchronisation entre marchés ;
* phénomènes météorologiques simultanés ;
* événements humains à la même heure.

Visuellement, les synchronisations peuvent apparaître sous forme de :

* lignes lumineuses reliant plusieurs points ;
* cercles concentriques ;
* pulsations simultanées ;
* regroupements temporels ;
* constellations.

⸻

L’utilisateur peut activer ou désactiver différentes dimensions.

7. LES TAXES DU MONDE

Créer une couche :

FISCALITÉ

L’objectif est de pouvoir comprendre comment fonctionne la fiscalité à travers les différents États.

Prévoir une architecture permettant d’afficher :

* TVA / taxes à la consommation ;
* impôt sur le revenu ;
* impôt sur les sociétés ;
* taxes spécifiques ;
* prélèvements ;
* grandes catégories fiscales.

Important :

Les informations doivent être structurées comme des données temporelles.

Une taxe possède :

* un pays ;
* une date d’entrée en vigueur ;
* une date de modification ;
* une évolution ;
* une période.

Ainsi, la Timeline permet de visualiser l’évolution de la fiscalité mondiale dans le temps.

13. LE CONCEPT DE « PARTITION VIVANTE »

Toute l’expérience doit être pensée comme une partition.

Chaque catégorie possède un rythme.

Par exemple :

* les marchés = rythme rapide ;
* les avions = mouvements continus ;
* les naissances = pulsations humaines ;
* les mariages = événements ponctuels ;
* les budgets = rythmes mensuels ou annuels ;
* la pollution = nappes et respirations ;
* les événements historiques = couches profondes.

Créer éventuellement une vue alternative :

PARTITION

Au lieu de la carte, les données sont représentées sur une grande Timeline horizontale.

Chaque dimension devient une piste.

Exemple :

17. ARCHITECTURE TECHNIQUE À PRÉPARER

Ne pas tenter de connecter immédiatement toutes les sources mondiales.

Créer plutôt une architecture de providers.

Exemple conceptuel :

DataProvider

Puis :

* FinanceProvider
* PopulationProvider
* BirthProvider
* MarriageProvider
* PublicFinanceProvider
* TaxProvider
* PovertyProvider
* FlightProvider
* MobilityProvider
* AirQualityProvider
* PollutionProvider
* EnergyProvider

Chaque provider doit respecter un format de données commun.

Créer notamment une structure universelle :

WorldEvent

Avec par exemple :

* id
* type
* category
* timestamp
* startDate
* endDate
* location
* country
* coordinates
* value
* unit
* source
* sourceUrl
* reliability
* updatedAt

Cette structure doit permettre de faire entrer différents types d’événements dans le même moteur temporel.

Cette page doit être connectée conceptuellement au World Model existant.

Les événements mondiaux doivent pouvoir être représentés comme des entités et relations.

Par exemple :

Un événement peut être relié à :

* un pays ;
* une population ;
* une entreprise ;
* une organisation ;
* une période ;
* un autre événement.

L’objectif est que la carte mondiale ne soit pas un écran isolé.

Elle doit devenir une surface de visualisation du World Model à l’échelle planétaire.

Dans un premier temps, créer un mode de démonstration spectaculaire.

Utiliser des données simulées clairement identifiées comme telles.

Le mode démo doit permettre de montrer simultanément :

* mouvements financiers ;
* variations ;
* naissances estimées ;
* mariages simulés ;
* vols ;
* zones de pollution ;

L’objectif est que l’expérience soit immédiatement impressionnante visuellement.

Ensuite seulement, chaque provider pourra être progressivement remplacé par une source réelle.

LA PARTITION VIVANTE DU MONDE

* les déplacements ;

AIME permet alors d’observer non seulement les données, mais aussi :

* les rythmes ;
